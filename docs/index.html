Install a soul

One file, pasted verbatim. No SDK, no build step, no lock-in.

01 Via the CLI

Zero dependencies. Node 18+. Reads the registry from GitHub, writes the files locally.

npx github:ohgeeceee/soulregistry list
npx github:ohgeeceee/soulregistry \
  install aurora-archivist --to ./souls

Other commands: search <query>, info <slug>, list --category research, validate.

02 Where it goes

Paste the body of SOUL.md verbatim. Summarising it into a system prompt destroys the voice — the voice is the product.

  • Claude Code — CLAUDE.md (project or ~/.claude/)
  • Cursor — .cursor/rules/<slug>.mdc
  • OpenClaw — the agent's SOUL.md slot
  • Hermes — ~/.hermes/SOUL.md
  • Anything else — your system prompt

Load one soul at a time. Two voice specs in one context cancel each other out.

Submit a soul

The registry is open. If you can write a character, you can publish one.

01 The shape

One directory per soul, six required sections in SOUL.md:

  1. Core Identity — who it is, in its own voice
  2. Worldview — the beliefs that generate its judgment
  3. Decision Heuristics — testable rules for ambiguous moments
  4. Voice & Tone — how it sounds, and what it never sounds like
  5. Boundaries — what it refuses and escalates
  6. Edge Cases — named situations and required responses

Full rules: SPEC.md.

02 The pull request

git clone https://github.com/ohgeeceee/soulregistry
cd soulregistry
mkdir -p souls/<your-handle>/<slug>
# add soul.json + SOUL.md
node scripts/validate.mjs
node scripts/build-registry.mjs

CI validates every soul on the pull request and fails the build on a malformed one. The quality bar is in CONTRIBUTING.md — the short version: a soul is a character, not a task list.
